# 灵影 Live · 数字人交互

**让 AI 的回答拥有声音与可见的讲述者。**

提出一个问题，听见解释，也看见数字人讲述。例如，学习一个新概念时，你可以先问“用生活中的例子解释一下”，阅读回答，再聆听人物讲解；需要换一种说法时，继续在同一工作台追问。

**灵影 Live（LingYing Live）将文字问答、语音与数字人视频连接到同一个对话工作台，让用户围绕角色展开交流。** 面向学习问答、知识讲解与虚拟讲述，项目正在探索更有临场感的 AI 交互，并逐步完善持续交流和视频制作体验。

## 02 三个核心亮点

### 让解释可以读、可以听，也有讲述者

文字便于回看，声音便于聆听，人物画面提供可见的交流对象。用户可以围绕问题理解内容，在同一个空间查看文字与人物，而无需在多个工具之间搬运回答。

### 保留熟悉的角色，按任务选择不同能力

人物形象、交流设定、声音与模型连接分别管理。用户可以保留一个熟悉的讲述者，再根据具体任务选择已接通的回答和媒体能力。角色的延续性与服务的可替换性，可以同时保留。

### 让声音与人物画面保持一致

已有播放器将音频与视频放在同一播放时钟上，片段到达后逐步播放，缓冲不足时一起等待和恢复。对用户而言，目标是让听到的声音与看到的人物保持一致，减少媒体错位带来的阅读和观看中断。

## 03 先把两个场景做好

### 学习问答：围绕一个问题继续解释

**谁会使用：** 正在自学的学生、需要复习概念的学习者。

**怎样使用：** 从一个具体问题开始，让数字人用例子解释，再追问不理解的地方。文字用于核对定义，声音和人物用于讲述；角色可以成为熟悉的交流入口。

**下一步变化：** 完善持续语音交流、真实设备操作、插话和回声处理，并用完整录屏呈现等待情况。知识可靠性也需要更清晰的资料来源与内容审阅，不能只依赖人物表达的自然程度。

### 知识讲解：让一段内容有清楚的讲述者

**谁会使用：** 教师、内容作者、需要解释概念或流程的团队。

**怎样使用：** 把已经整理好的解释交给所选角色讲述，查看文字、试听配音，再使用人物视频表达内容。对已有录音，也可以探索直接生成相应人物片段。

**下一步变化：** 将独立视频制作入口与真实任务、预览、失败恢复及最终文件连接起来，形成从讲稿到视频的连续制作体验。

虚拟讲述和服务接待等方向可以在此基础上继续探索。当前优先关注交流能否持续、内容是否清楚，以及输出能否稳定取得。

## 04 从交流到内容制作

除了对话，灵影 Live 还面向数字人视频生成：使用文字或已有录音，选择人物与输出设置，组织一次制作任务。它与侧重完整课程的 [灵影 Studio](https://github.com/maolinqi/LingYing-Studio-Showcase) 分工不同，Live 聚焦人物交互与讲述，Studio 聚焦教学材料、课程编辑与课程交付。

## 05 已有、开发中与规划

| 状态 | 当前范围 |
| :--- | :--- |
| **已有** | 重构工作台、角色编辑与预览、回答 API 与流式文字、百度配音和识别、Pro 人物输出与播放器接入记录。 |
| **开发中** | 独立视频制作的完整生产接入，角色与对话对象的服务端持久化，以及持续交流和设备体验的完善。 |
| **规划与待验收** | 真实整轮连续演示、首帧与端到端等待测量、多轮和并发评估、回声与插话验收；克隆声音、角色知识文件等扩展按后端支持逐步接入。 |

流式播放为较早开始观看提供基础，实际等待仍来自回答、配音、视频推理与网络。当前没有完整连续交互录屏，也没有统一协议测量的稳定延迟或多人并发承诺。

### 技术怎样服务体验

回答使用用户配置的 DeepSeek API 或兼容接口，语音使用已接通的百度服务，人物视频沿用已有 [SoulX-FlashHead](https://github.com/Soul-AILab/SoulX-FlashHead) Pro 链路。模型连接集中管理，播放器复用已有音画同步和缓冲恢复机制。具体模型是否可用，以有效连接与实际请求为准。

连接元数据与模型选择可以保留；当前前端的 API 密钥和额外请求头保留在页面内存，刷新后需要重新提供有效凭据。独立制作页的演示进度和下载配置，不作为实际 MP4。
